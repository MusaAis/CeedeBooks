# Autopay for an earned vendor, first live run (Nov 6 to 7, 2026)

**Feature:** the owner's wallet-signed per-vendor autopay switch (`agent/autopay.py`, the Earned vendors panel in the admin Vendors tab, `POST /admin/autopay/*`, v1.3.3.1, Phase R piece 2). **Where:** the production API and the admin site, on the builder's own business (`ceedebooks`), with our own test vendor "ceedebooks test 2" (vendor 6, the owner's own wallet `0xae16d350...753eaaa`). One on-chain payment was made: a **0.01 USDC testnet shadow mirror**, from the agent wallet to the owner's own wallet. All times are UTC.

## What was run

1. The v1.3.3.1 files were extracted on the server (checksum `5f091b4f...662f2` checked, exactly the 23 expected files). The full Python suite ran there with the CI placeholder variables (**741 passed**, 6 minutes 39 seconds) and the Node suites passed (`JS_TESTS_OK`, `ADMIN_SMOKE_OK` twice). The database was backed up (`~/backups/ceedebooks.db.pre-1.3.3.1`, 266240 bytes), the API restarted (200 on `/businesses`), and the admin and proof-page files were copied. The Vendors tab showed a cap box and "Turn autopay on" on the graduated vendor only (a phone screenshot).
2. **Baseline, before anything:** `/stats` paid 1, held 0, escalated 2; `/ledger/verify` `ok`, 27 entries, 0 problems; 0 switches, 0 autopay records, 0 invoices with `auto` set.
3. **Switch on (23:55:16).** With the owner's yes, a cap of **0.5 USDC** was typed and the owner signed the message in the wallet. The message the admin site showed (screenshot) named the vendor and wallet, the cap "0.5 USDC per payment", what the agent may then do, that a hold, an escalation, a refused payment or a disagreement turns it off, a nonce, and a five-minute expiry, and said that signing sends no transaction and costs nothing. The row then read "autopay on, up to 0.5 USDC".
4. **One shadow invoice (00:01:43).** With the owner's yes: purchase order `AP-TEST-1` (0.01 USDC, vendor 6, category Data Oracle), receipt confirmed, then shadow invoice `AP-TEST-1-INV` (real bill 10 NGN, mirrored as 0.01 USDC). The admin site showed it as shadow, auto and paid with no approval button.
5. **A verdict (00:03:15).** The owner pressed "I agree" on the autopaid invoice.
6. **Switch off (00:09:26).** With the owner's yes, the owner pressed "Turn off".

## What went wrong, and what was not captured

- The first version of the check command for step 4 named a column that does not exist (`tx_hash`; it is `onchain_tx_id`), a mistake in the instructions and not in the product. It was corrected and re-run, and the output above is from the corrected run.
- The owner pressed "I agree" before the first check ran, so a count of zero verdicts could not be shown; the comparison of the verdict time (00:03:15) with the payment time (00:01:43) is what shows the agent did not make it.
- Not captured: the commit transaction of the commit-then-pay pair (the page's Verify shows the pay transaction; the commit transaction's hash was not read), the invoice's on-chain transaction id was read but not compared with the explorer, the `shadow` part of the traction response (the output was cut at 400 characters, so `auto_paid` and `auto_mirrored_usdc` were not read live), the on-page Verify on the `AUTOPAY ON` and `AUTOPAY OFF` records, and the `/stats` reading and the `AUTOPAY OFF` chip on the proof page after the switch was turned off.
- **Not run live:** the turn-offs by a hold, by an escalation, by a refusal from the contract and by a disagreement; the cap refusing an amount above it; a lost graduation; a changed wallet. They are covered by tests only. A disagreement would add a permanent "I would not" to the public agreement record, and a refusal by the contract needs a payment the contract would reject, so neither was provoked.

## What changed afterwards

Nothing in the code. The first live run matched the tests: the payment was a labelled shadow mirror and moved no live figure, and the turn-off was written as a record.
