# Red team run: the contract refuses an unapproved payee (Oct 15, 2026)

**Feature:** `scripts/red_team.py` (v1.2.9.4, Phase E4). **Where:** the original business, the v1 `BudgetEnforcer` at `0x47D8a05a0d31aFA492A9F4A37A8991ED4aa683fB`, run from the server by the owner, who typed `yes` before each on-chain step. **When:** about 09:46 UTC.

## What was run

The agent wallet `0x32B59A6988DCA955c641D529Ee80484200DE37b0` tried to pay a fresh address that is not an approved vendor, `0x645165125d198C360f96D6a13807907159d83741`, for 1 unit.

1. Audit row `RED_TEAM_REFUSED` written first. `reasoning_hash` `d7ea640ae468f2e2dec1dc35ac05c7f1f2ca006b47b0f0cc00c001204fddb2a0`.
2. `commitDecision` sent and confirmed: [`0xb4c4b271...6e0b780`](https://explorer.testnet.arc.io/tx/0xb4c4b271b3bb9b43c8d00cedf5e633c0c7a6085360864508ab8b0cb766e0b780), block 67310235 (09:46:47 UTC). Its hash was not printed during the run; it was found afterwards, on Oct 23, as the only `DecisionCommitted` event in the 600 blocks before the anchor transaction (the commitment value was not recomputed).
3. `pay` refused: `Transaction 724d9522-a1c3-5c54-861d-b656db1e2128 FAILED: ESTIMATION_ERROR - execution reverted: Vendor not approved`.
4. The ledger head was anchored: sequence 16, head `7526aeb8f6b3c583460399253ca240dc049a4e4096a02596416f1d7f7383c16b`, transaction [`0x2f75bf9f9aa5702e68c5c031f58f79d56e1c0b68e22567c44d46c3ca4b0509af`](https://explorer.testnet.arc.io/tx/0x2f75bf9f9aa5702e68c5c031f58f79d56e1c0b68e22567c44d46c3ca4b0509af).

## Result

The contract's own check (`Vendor not approved`) stopped the payment. Afterwards `GET /ledger/verify?business=ceedebooks` returned `ok` true, 17 entries, 16 decisions, 0 problems, anchor `match`, no entries after the anchor, `fully_verified` true.

## What was not captured, stated plainly

- The refusal came from Circle's gas estimation, so no `pay` transaction reached the chain. **There is no pay transaction hash to link.** The revert reason is the contract's.
- The record on the proof page reads "manual entry, off-chain only": the row itself is not an on-chain event. The anchored head that includes it is.

## What changed afterwards

The run was written into the README Traction section and the v1.2.9.4 changelog entry (v1.2.10.1 rewrite). The script stops loudly if the contract does not refuse.

## Check it yourself

- Open the anchor transaction above on the explorer.
- `curl https://api.ceedebooks.xyz/ledger/verify?business=ceedebooks` and read `anchor` and `fully_verified`.
- On https://ceedebooks.xyz press "Verify the whole chain".
