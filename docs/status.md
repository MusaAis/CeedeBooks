# Status

Where the project stands: the newest release in full, then the ones before it. The short version is on the [README](../README.md); every release is in the [changelog](../CHANGELOG.md).

## Read this first

Everything runs on Arc Testnet with test USDC. Two businesses exist and both are ours: no outside business or paying user yet, and every payment so far is self-owned. The `MilestoneEscrow` contract is a reference deployment for our own testing: it holds only our own testnet funds and no outside party has used it; the agent's release path has been run live once, on milestone 0 with a stand-in merged pull request, and the approver's own pause, withdraw, reject, release and resume were each run live once on Oct 29 (all our own wallets; the milestones' work is a stand-in, not delivered work); its source is not verified on the explorer. Idle-cash yield is planned, not built. Limits and guarantees: [trust model](trust-model.md).

## Latest releases

**v1.3.3.3**: documentation only. The README became a short front page and this page, the evidence page and the Sep 27 page took the detail. No code changed.

**v1.3.3.2**, Phase R piece 3 (vendor trust on the proof page and in the admin site, with a documentation correction): a public, read-only route `GET /businesses/{slug}/vendor-trust` and a "Vendor trust" block on the proof page show, for each vendor with a streak or a trust record, its streak against the owner's threshold, whether it is graduated, whether the owner's autopay switch is on (and its per-payment cap), how many shadow invoices autopay paid, and its graduation, revocation and autopay records, each with a hash and a "Check it" button that verifies it. The admin Vendors tab shows the same records and a revocation count for every vendor. It reads records and writes nothing: no payment, no figure, no ledger entry. Built and tested (14 new route tests, 11 for the docs checker; proof page and admin site checked in a headless browser); nothing in it needs a live run beyond reading it.

**v1.3.3.1** (Phase R piece 2, autopay for an earned vendor): the owner's wallet-signed per-vendor switch, built and tested, and run live once on Nov 6 to 7 (one switch on, one 0.01 USDC autopaid shadow invoice on our own test vendor, one switch off; revocation by a hold, an escalation, a contract refusal or a disagreement not run live; [record](rollouts/2026-11-07-autopay-live.md)). For one graduated vendor the owner signs a message (it names the vendor, its wallet and a per-payment cap, and sends no transaction), and the agent then pays that vendor's next shadow invoice without an owner click, but only if every existing check passes: the three-way match, the rules, the pause, and the contract's own limits and vendor approval. Any hold, any escalation, a refusal by the contract, or a later disagreement from the owner turns the switch off and writes that as a ledger record. These payments stay in the shadow bucket, labelled `auto`, are never added to the live figures and never count as outside traction.

**Before it:** v1.3.3 (Phase R piece 1, earned vendors: the rule and the record), built and tested, and run live once on Oct 31 (one graduation on our own business, no payment; revocation not run live; [record](rollouts/2026-10-31-earned-vendors-graduation-live.md)). An owner sets a number N (default 5, from 2 to 50). When the owner has approved the agent's last N shadow pay decisions on one vendor in a row, the vendor is *graduated*: a ledger record, hashed and signed like every decision, saying when and why. One disagreement (a rejected pay, or an "I would not" verdict on that vendor) revokes it, also as a ledger record. A graduation pays nothing and changes no limit: in v1.3.3 nothing paid a vendor by itself, and every payment needed the owner's approval and passes the contract's own checks. The admin Vendors tab sets N and shows each vendor's streak; the proof page feed labels the records Graduated and Revoked. Details: [CHANGELOG](../CHANGELOG.md) and [features](features.md).
