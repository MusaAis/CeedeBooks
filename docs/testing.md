# Testing

Run these from the repository root after the [setup](../README.md#setup).

```bash
forge build && forge test -vv
ARC_TESTNET_RPC_URL=http://localhost:8545 DEPLOYER_PRIVATE_KEY=0x01 GROQ_API_KEY=ci-placeholder \
  BUDGET_ENFORCER_ADDRESS=0x47D8a05a0d31aFA492A9F4A37A8991ED4aa683fB CIRCLE_API_KEY=ci-placeholder \
  CIRCLE_ENTITY_SECRET=ci-placeholder python -m pytest agent/tests -q
node site/verify.test.js
node admin/wallet.test.js && node admin/admin.test.js && BIZ=acme node admin/admin.test.js
node portal/portal.test.js && node portal/business.test.js
```

The pytest run needs only these placeholders: the chain and Circle's calls are faked. Importing `agent/contract.py` still creates the Circle client, so the machine needs network access to Circle's API host (CI has it). `forge build` comes first because the wallet and portal Node tests read the compiled contracts in `out/`.

**111 Foundry tests** (24 for the v1 contract, 35 for `BudgetEnforcerV2`, 6 for `BudgetFactory`, 4 for `LedgerAnchor`, 42 for `MilestoneEscrow`), one per revert path or acceptance scenario: unregistered and revoked vendor, over per-tx / daily / category limits, unset category (fail-closed), same invoice resubmitted as a different file, missing / reused / mismatched commit, crash-and-retry, simulated prompt injection (contract refuses even if the agent were fooled), the escalate → approve / reject flow, escalated invoices blocked from direct payment, pause, withdraw, agent rotation, two-step approver rotation, and the `reasoningHash` round-trip via the `PaymentMade` event. The 42 escrow tests cover the happy path, a double release, the wrong agent, no commit, a commit in the same block, a commitment from another escrow, for another milestone or chain, the approver-only limit, reject then override, a withdraw that cannot touch Pending amounts (with a fuzz test), pause behaviour for the agent and the approver, an unfunded escrow, bad constructor roles and milestones, and agent and approver rotation. Six of the escrow guards were broken on purpose (same-block release, the approver limit, the reserved balance, the pause check, commitment reuse, the contract binding) and each break failed a test. `forge build` needs the solc 0.8.20 download; a network that blocks it needs a local `solc` and `forge test --use <path>`.

**642 Python tests** in `agent/tests/`. No test sends a transaction or reaches an outside network (one test opens a socket to a server on the same machine to read the connected address). They cover:
- The decision pipeline: three-way match, rules baseline (pay, hold, escalate), retry safety, the 0.01 USDC rounding allowance, and the invoice pre-flight dry run, which writes nothing and reveals no balances.
- Access control: API keys and roles, vendor wallet sessions, admin wallet sign-in, and every denied path.
- Multiple businesses: isolation (a key, session or id of one business never reaches another), hash formats 1 to 3, onboarding and its on-chain checks, per-business categories, and shadow mode.
- The ledger and audit trail: the signed chain (edited, deleted, reordered or forked entries, a wrong key), the on-chain anchor, the public verify endpoints, the archive flag and the relabel tool.
- The model: the rules verdict always acts, a disagreeing or slow model changes nothing, no answer is null and never agreement, and model text with invented figures is withheld.
- The Gateway read: the request body matches Circle's documented shape, other domains and depositors are not counted, and every failure (status, shape, number, timeout, bad address) is null, never zero.
- The Gateway deposit script: amount bounds and the 5 USDC cap, the two calls' signatures, the order (audit row, approve, deposit), an exact-amount approval, a declined step sends nothing, and an unreadable chain, a wrong agent, a missing contract or too small a balance sends nothing. Each check was broken on purpose to confirm a test fails.
- Oversight (v1.3.0): figures (a placeholder is filled, a digit or an unknown placeholder is refused, a reply with its own digits is replaced by the code-written reason), pause (a paused invoice is held with its marker and nothing is sent, an unreadable pause state pays nothing, a re-run only after resume, the record must match the contract and carry a real reason, the ledger entry verifies, the banner is unknown when unreadable, an emergency stop stands without a ledger key, a shadow approval while paused keeps waiting) and maker-checker (the submitter is recorded, the release key is refused to the submitter, a hand-made release is flagged, a second settlement is refused, the invoice list never shows who else submitted). Six of the guards were broken on purpose to confirm a test fails.
- Traction origin (v1.3.1.2): `live` and the latest paid list count the agent's own traffic only; manual and demo invoices appear in `not_traction` and never in the live figures; shadow payments stay listed; a demo payment alone leaves the traction empty. Both guards were broken on purpose and each was caught.
- Demo path (v1.3.1.1): the three invoices go through the real pipeline and are all origin `demo`; the reasons are the real ones; an approved demo vendor is paid 0.01 USDC at the owner's wallet; demo decisions stay out of the agent totals, traction and the Outcomes agent figures; the feed marks demo rows and only them; the ledger still verifies; the two-a-day limit; only a wallet-signed admin can seed; no usable category, an unreadable chain and a failure on one invoice are handled; a business seeds only itself.
- Outcomes (v1.3.1): the decided-alone, escalated and person-agreement counts (a release by a person is never counted as the agent's own payment, and one business's release is never credited to another's invoice), the null cases, the median over stamped agent payments only, the own and outside split, the origin split, shadow and archived exclusion, the one-business scope, no private field in the response, and that each SQL statement shown runs as written. Seven of the guards were broken on purpose to confirm a test fails.
- Escrow reads and the fetch rules (v1.3.2.1): non-public addresses of every kind (private, loopback, link-local, shared, multicast, IPv4-mapped, NAT64, 6to4), lookalike and userinfo hosts, other schemes and ports, a name that resolves to a private address, a connection that reached a private or unknown address, redirects, size and time caps, a bad status or body; the pull-request facts and hash (free text never enters it, a wrong repository or shape is a failure) and invalid targets sent nowhere; registration (the agent, approver and USDC checks, the unreadable chain, duplicates, an archived business, rate limits), tenant isolation, the public routes, the cache, and that the escrow code has no way to send a transaction. Eighteen of the guards were broken on purpose and each break failed a test; the first run missed the streamed size cap, which showed a gap in a test that was then fixed.
- Return to agent and re-run (only v2, only the matching event, one click at a time, another business's invoice is untouchable) and the red-team script (a refusal is recorded, an acceptance is a loud failure, a declined step sends nothing).

**Node suites** run the browser code without a browser: the proof page's hash recomputation and whole-chain check against a real Ed25519-signed chain, with contract selectors compared to the compiled contracts (`site/verify.test.js`, which also covers the Outcomes view: own and outside apart, the rate with its count, a missing figure said plainly); the admin app's call encoding and rendering, including the disabled release button, the pause reason and the banner (`admin/*.test.js`, the admin one also run as a second business); and the vendor portal and business registration page (`portal/*.test.js`).
